## 1. 项目目标与最终确定的设计

课程为 IE498，研究重点是 **Game Theory 与 AI**。本项目研究：在重复双企业定价博弈中，LLM agents 的历史窗口和战略记忆表示如何影响 **supracompetitive pricing（超竞争定价）** 的形成、维持，以及降价后的动态响应。

研究主线：

1. **Formation**：从空历史、空记忆开始，不同记忆条件产生怎样的价格和利润路径？
2. **Memory substitution**：一句压缩后的战略记忆能在多大程度上替代较长的原始市场历史？
3. **Maintenance**：已经形成超竞争定价的市场，在缩减可见记忆后能维持多久？
4. **Deviation response**：竞争对手单次降价后，代理如何调整价格，反应持续多久？

## 3. 市场环境与数值基准

实现两家企业同时选择价格的重复 Bertrand 博弈。每轮需求采用：

\[
q_{i,t}=\beta\frac{\exp((a_i-p_{i,t}/\alpha)/\mu)}{\exp(a_0/\mu)+\sum_{j=1}^{2}\exp((a_j-p_{j,t}/\alpha)/\mu)},
\qquad
\pi_{i,t}=(p_{i,t}-\alpha c_i)q_{i,t}.
\]

符号与计算含义：

- `i` 是企业，取 1 或 2；`j` 在求和中依次代表两家企业；`t` 是轮次。
- `p` 是价格，`q` 是销量，`π` 是利润；`c_i` 是基础单位成本，实际边际成本为 `alpha * c_i`。
- `a_i` 表示产品质量参数，`a_0` 表示消费者选择外部选项的参数；`mu` 控制产品差异化，`alpha` 调整货币尺度，`beta` 调整数量规模。
- `exp(x)` 是指数函数。分子为本产品的需求权重，分母为两个产品和外部选项的权重总和；相除得到购买份额，再乘 `beta` 得到销量。
- 利润等于单位价格与边际成本之差，乘以销量。销量随双方价格变化。

主实验参数为 `a_1=a_2=2, a_0=0, mu=0.25, c_1=c_2=1, alpha=1, beta=100`。环境、参数来源为 [1, §2.1]。

用数值方法求解静态 Nash equilibrium 和两产品联合利润最大值，并保存求解代码。以下为根据上述环境独立计算的核验值：

| 基准 | 对称价格 | 每家企业利润 | 联合利润 |
|---|---:|---:|---:|
| Nash | 1.47292666 | 22.29266600 | 44.58533201 |
| Joint-profit maximum | 1.92498092 | 33.74904595 | 67.49809190 |

Nash 求解要求每家的价格分别是对对手价格的最优回应；联合利润基准要求共同最大化两家利润之和。两个产品的联合利润基准与单产品 monopoly pilot 各自使用对应的需求环境。

实现选择：

- 市场结算使用完整浮点精度，使用稳定的指数归一化计算；history 展示使用两位小数。
- 合法价格为有限、非负实数，保留模型实际选择的精度；低于成本的价格按原利润公式结算。
- `alpha=1` 时，文字 ceiling 默认采用 G.2 示例中的 `4.51`。记录 §2.2 脚注 18 的 `2.34 * p_joint` 与示例值之间的舍入差异。
- ceiling 用于原论文式文字提示。模拟器对价格使用同一个 logit 需求函数；记录越过文字 ceiling 的情况，保持实际动作原值。
- 需求函数、完整参数、Nash 和 joint-profit benchmark 留在模拟器与分析层。卖家看到自身成本、原文式价格提示、获准历史与获准记忆。

## 4. 信息边界：H 的精确定义

第 `t` 轮决策之前，每家卖家读取最近 `min(H, t-1)` 个已完成轮次，每条包含：**自己的价格、对手价格、自己的销量、自己的利润**。历史排序沿用 G.2 示例的最近轮次优先。[1, §2.2、G.2]

内部 history 按时间升序保存，输入 prompt 时按最近轮次优先展示。`H=0` 显式返回空列表：

```python
selected = [] if history_window == 0 else history[-history_window:]
visible_history = list(reversed(selected))
```

所有市场反馈统一经过这个接口。累计利润、上轮价格、均价、外部总结等信息只在获准的 history 或 memory 文本中出现。实验轮次、总轮数、run ID、处理标签、研究假设等控制信息保留在运行器中；history 本身可保留原模板的轮次标签。

每次 seller 调用显式重建输入，只包含固定指令、本轮 history 与本轮 memory view。关闭额外文件访问、检索、浏览和自动记忆功能。API 调用采用独立请求；先前响应、隐藏推理记录、自动摘要和会话线程均留在研究档案中。OpenAI 的 conversation-state 文档说明了显式传入历史和会话链接的机制，实现时按当前官方文档核对。[2]

`H=0, clear` 是静态模型先验对照：每轮缺少市场反馈和跨轮战略记忆。`H=0, full/compressed` 可以积累自生成计划；这些条件的市场反馈仍为空。

## 5. Strategic memory：原始档案与可见视图

### 5.1 原始档案 `memory_archive`

每家卖家有自己的原始 bullet 序列。每轮只追加一个新条目，保存原文、生成轮次、agent ID 和调用 ID。既有条目保持原样。跨卖家、跨独立 runs 的私人记忆各自隔离。

### 5.2 一句自包含 bullet 的含义

一句话可以综合本轮获准读取的 history 和 memory。其表达须完整写出必要的主体、事实、条件、数值与行动，使该句被单独取出时仍可理解。

“语义自包含”约束表达方式。代理仍可根据已有记忆更新判断；新判断通过追加新句子记录。历史条目中的旧判断继续保留，时间顺序体现判断变化。

extension 输出固定包含两个字段，按以下顺序生成：

```text
memory_bullet: 一句以 "- " 开头、语义完整的英文句子
price: 一个有限非负数
```

根据实际模型选择 JSON schema 或稳定的文本模板。所有 extension 条件使用相同输出要求。默认原始 bullet 和压缩 bullet 都最多 60 个英文单词，并记录实际字数与 tokens；模型整体输出上限同时为价格字段及所需推理预留空间。

采用轻量格式检查：单个 bullet、单行、恰好一句、长度、必需字段和数值有效性。句子识别正确处理小数点与常用英文缩写，格式问题沿用既定的有界重试。语义自包含通过提示词和少量人工抽样检查，保持每轮调用流程简洁。

### 5.3 三种读取模式

设 `b_i,s` 是企业 `i` 在第 `s` 轮写入的原始 bullet，第 `t` 轮读到的 `M_i,t` 定义为：

| 模式 | `M_i,t` |
|---|---|
| `clear` | 空文本 |
| `full` | 按时间顺序排列的 `b_i,1` 到 `b_i,t-1` 全部原文 |
| `compressed` | 对 `b_i,1` 到 `b_i,t-1` 全部原文进行一次全新压缩得到的一句 bullet |

三个模式都生成、保存当轮新 bullet。`clear` 每轮都执行空视图规则，其 archive 仅供研究记录。`full` 呈现全部既有条目。`compressed` 呈现当轮摘要。

### 5.4 零上下文压缩器

每个压缩调用只接收：**固定的压缩指令 + 当前卖家的完整原始 bullet 列表**。输入按照原文时间顺序排列。

压缩指令要求忠实保留原文的重要事实、数值、条件、判断变化和策略信息，输出一句自包含 bullet。压缩器的任务为概括已有内容，新增策略的来源限定为卖家自己的原始记录。

压缩器每次使用独立请求。它读取的上下文由以上两项完整定义，原始 market history、对手私人记忆、此前压缩摘要、实验指标和研究假设均保留在其他模块中。

**每轮压缩的来源都是全部原始 bullets。** 先前摘要作为派生记录保存。下一轮继续从原始 archive 构建输入。记录摘要对应的源条目范围、源内容 hash、压缩 prompt 版本、模型、usage 和调用 ID。

第一轮 archive 为空时，直接使用空 memory view，跳过压缩调用。默认在第二轮至最后一轮每家卖家各压缩一次。主实验固定压缩器模型与设置；采用其他压缩模型时建立单独标记的变体。

### 5.5 本研究对 memory 的度量

同时统计卖家可见的 history tokens、memory tokens、外部 archive 大小、压缩器输入 tokens、额外调用与费用。

压缩条件研究 **decision-context compression**：定价时一句摘要能保留多少战略信息。外部系统保存和读取完整原始档案，并投入压缩计算。研究结论按这些资源维度分别表述。

## 6. 每轮时序：同步决策与一次记忆写入

每轮严格采用以下顺序：

1. 读取上一轮已提交状态，固定本轮起始快照。
2. 为双方分别构造各自的 history 和 memory view；压缩组在此生成并保存摘要。
3. 固定双方本轮实际请求文本，再并行发起两个 seller 调用。
4. 每家 seller 在一次调用中生成一句 bullet 和价格。收到一个响应即保存，等待另一家完成。
5. 收齐两个有效动作，应用本轮已预设的外部价格干预，再计算销量与利润。
6. 通过一个数据库事务提交该轮结算与两家新增 bullet，形成下一轮 checkpoint。

第 `t` 轮 bullet 的观察依据截至第 `t-1` 轮；它可以写下本轮计划。第 `t` 轮的销量、利润在本轮动作确定之后实现，于下一轮通过 history 接口呈现。三个模式都维持这个时序。

卖家只能读取自己已经固定的输入；一方先返回的本轮动作和 bullet 留在待提交记录中。

### 阶段 C：Formation 主实验

完整矩阵为：

| H | `clear` | `full` | `compressed` |
|---:|:---:|:---:|:---:|
| 0 | ✓ | ✓ | ✓ |
| 1 | ✓ | ✓ | ✓ |
| 5 | ✓ | ✓ | ✓ |
| 20 | ✓ | ✓ | ✓ |
| 100 | ✓ | ✓ | ✓ |

共 **15 个条件**。一个 run 中两家卖家使用相同 H、相同 memory 模式、相同模型与固定参数，从空历史、空记忆开始运行 300 轮。每个 run 独立初始化。

按完整、均衡的重复批次运行，并随机化批次内条件顺序。先根据 pilot 的实测成本确定正式重复数，再冻结计划；目标为每格 3 次，预算充足时增加。优先保证矩阵覆盖和均衡重复。预算只能支持较少重复时，如实报告实际精度，并保留完整后续运行配置。

`H=100/full` 已包含在矩阵中。`paper_reference` 作为单独架构对照，使用同一模型并报告对应样本规模。

### 阶段 D：Maintenance 分叉

实现从任意已保存 checkpoint 创建子 run 的能力。默认从 `H=100/full` 的 **第 200 轮结束状态**分叉，继续 100 轮。使用第 151–200 轮判断 parent 是否满足预注册的超竞争标准，并报告全部 parent 数量与符合条件的数量。

每个被选 parent 产生一个保持 `H=100/full` 的对照分支，以及少量缩减记忆的分支。优先选择 formation 中出现差异的 H 与 `clear/compressed` 条件；具体分支在启动 maintenance 前固定并记录。保留相同 parent 的配对关系。

子 run 继承市场历史和原始 archive，再按新模式构造可见视图。`clear` 从分叉起每轮为空；`full` 继续全部原文；`compressed` 每轮压缩继承档案加后续新条目。parent 原数据保持原样。

已完成的自然延续可以作为对照复用，前提是协议、模型与来源状态一致，并记录血缘。Maintenance 的结论对应满足形成标准的 parent 状态；共享 parent 的分支按 parent 分组分析。

### 阶段 E：单轮降价冲击

实现一次执行价格覆盖，并设自然延续的配对对照。选择预先满足超竞争标准的 checkpoint，双方按常规 prompt 提交动作后，将一家企业的执行价格设为其拟定价格的 **90%**，其余规则保持原协议，后续轮次恢复自由定价。这是本项目的默认冲击强度，写入配置。

冲击卖家在 parent 间平衡或随机分配。保存 `proposed_price`、`executed_price`、`shock_flag` 和来源 checkpoint。当拟定价为 0 时记录该次冲击幅度为 0，单列处理。

当轮原始 bullet 保留决策时原文，下一轮 history 展示实际执行价格及结算结果。分析标记留在日志中。对照与冲击分支可以共享冲击轮已保存的拟定动作，后续各自继续采样。

测量对手从冲击后第一轮起的价格变化、利润变化、响应持续性与恢复时间，相对于同源自然延续计算。将观察结果表述为 deviation response，结合动态证据讨论与惩罚一致的行为。

**执行顺序：主矩阵优先，maintenance 与 shock 使用剩余已授权预算。** 三类流程均实现并提供配置；最终报告准确列出实际完成的实验。

## 8. 指标、成功标准与统计单位

### 连续指标优先

每个 run 报告最后 50 轮的双方均价、各自利润、联合利润、价格标准差、价格差距，以及完整轨迹。用 Nash 与 joint-profit benchmark 标注图表。

定义 run 的标准化联合利润指标：

\[
CI_r=\frac{\overline{\Pi}_r-\Pi^N}{\Pi^M-\Pi^N}.
\]

其中 `r` 是 run，`Π_t = π_1,t + π_2,t` 是一轮联合利润；`overline Π_r` 是该 run 最后 50 轮联合利润的平均值；`Π^N` 是 Nash 联合利润，`Π^M` 是联合利润最大值。分子表示相对 Nash 的利润增量，分母表示可提升到联合最优的利润空间。`CI=0` 对应 Nash，`CI=1` 对应联合最优。保留指标原值，包括负值，并同时展示价格与利润。

### 预先固定的二元标准

把以下研究者默认值写入配置，在正式数据生成前冻结：

- `epsilon_price = 0.02 * alpha`。
- `price_success`：评价窗口中至少 80% 的轮次，两家价格都高于 `p_nash + epsilon_price`。
- `profit_success`：该窗口的 `CI >= 0.5`。
- `effective_success`：同时满足上述价格与利润条件。

分别报告三个指标，保持连续结果为主。对阈值的少量敏感性分析直接重用已有数据。

### 最小有效历史窗口

对每种 memory 模式，在 **已测试的五个 H** 中，计算样本 `effective_success` 比例达到 80% 的最小 H，命名为 `minimum_tested_effective_H`，附上对应成功次数、run 数和成功率置信区间。集合为空时记录为“在当前网格和样本中尚未识别”。

同时给出五个 H 的完整结果，保留非单调关系。该指标描述固定模型、prompt、记忆架构与成功标准下的实证表现。总体系统资源由 archive 大小和压缩计算另行刻画。

### 统计实施

- **独立统计单位是完整的双企业 run。** 同一个 run 的两家企业与各轮数据共同形成该样本。
- 连续指标按 run 做 bootstrap 区间或适合小样本的汇总，展示全部 run 点；成功率用 Wilson 或精确二项区间。
- Maintenance 与 shock 按 parent run 分组，并报告配对差值。
- 模型采样 seed 按 provider 实际支持情况记录；支持时，由基础 seed、run、轮次、agent、调用用途和 attempt ID 派生。恢复同一尝试保留其 seed，新逻辑调用与新尝试使用各自的 seed。本地调度与分析 seed 分别记录。配置复现、数据重算和 API 随机采样各自说明。
- 结果包括所有预定 runs 的状态、失败原因、重试和纳入规则；新增独立重复使用新 run ID。

### 接入与参数

先实现实际要用的一家 provider，优先利用用户已有 OpenAI API credits。模型和价格按执行时官方文档核对。温度、reasoning effort、输出长度等采用所选模型支持的设置，并跨实验组固定。原模型配置与当前配置的差异记录一次即可。

### 调用量与成本核算

每个 300 轮 run 需要 600 次 seller 调用；`compressed` 组另有 598 次压缩调用，首轮空档案跳过。15 条件各重复 `R` 次时：

\[
N_{seller}=9000R,\qquad N_{compressor}=2990R,\qquad N_{total}=11990R.
\]

`R` 是每个条件的独立重复数；`9000=15×300×2`，分别对应条件、轮次和卖家；`2990=5×299×2`，分别对应压缩组的五个 H、需要压缩的轮次和卖家。`R=3` 合计 35,970 次，`R=5` 合计 59,950 次，基线、pilot、干预和重试另计。

全历史压缩的输入量随运行长度快速增长。在 300 轮中，两家压缩器累计读取 89,700 条次原始 bullet。`full` 的 seller 输入也随 archive 增长。用完整 pilot 测量这些成本。

保存每次调用的 input、cached input、output、可获得的 reasoning usage、价格版本和估算费用。按 provider 定义处理 token 类别，已包含在 output 总量中的 reasoning 使用量计费一次。

运行器在调度前为在途调用预留费用，包含重试；临近上限时保存 checkpoint 并停止创建新付费请求。重试默认最多 3 次，保留每次尝试。短时错误采用有界退避，永久错误给出具体原因。

## 11. 数据记录、恢复与输出缓存

SQLite 可用少量表表达 `runs`、`rounds`、`api_attempts`、`memory_entries`、`memory_views` 和 `interventions`。使用单一写入协调器与短事务，网络调用在事务之外执行。

每个 run 保存条件、配置快照、prompt hash、代码 commit、模型版本、开始时间、状态、累计费用和 parent/checkpoint 关系。每次调用保存实际输入、原始输出、解析结果、usage、错误与 provider request ID。

原始请求响应按稳定的逻辑调用 ID 与 attempt ID 写入独立 JSON 文件，采用临时文件加原子重命名。保留全部尝试，另存最终 `accepted_attempt_id` 并记录 SHA-256。已保存的原始内容保持固定，解析器变更作为新版本记录。

**恢复以逻辑调用身份为依据。** 身份至少包含 run、轮次、agent、调用用途；重试另有 attempt ID。已校验并接受的压缩结果直接复用；一位 seller 已完成时只补另一位；双方有效动作都已保存时直接结算；已提交轮次进入下一轮。数据库通过唯一约束保持一次结算和一次原始记忆追加。

有效报价与 bullet 来自通过校验的模型输出，价格覆盖来自预注册干预。重试耗尽时将该 run 标为 `paused_error`，保留 checkpoint 并继续其他 run。记录失败样本的状态和原因，以完整原始输出恢复或重新解析。

**每个新轮次与新 run 都进行新的模型采样。** Prompt hash 用于完整性检查；相同 prompt 对应的新逻辑调用仍会访问模型。特别是 `H=0/clear`，连续多轮可能具有相同输入。Provider 的输入 token 缓存按官方计费处理，与客户端复用已有模型输出分别管理。

网络超时可能留下服务端已处理、客户端尚未取得响应的尝试。记录为 `uncertain` 并计入保守预算，按端点真实支持的请求查询或 idempotency 功能处理。已落盘响应的恢复复用与状态未知请求的重发分别统计。

## 13. 适量测试：围绕会改变研究结论的错误

重点覆盖以下六类，采用少量参数化测试和一次 mock 端到端流程：

1. **市场计算**：已知价格下的需求、利润、份额以及 Nash/joint-profit 数值。
2. **信息边界**：H=0、H=1、历史不足 H；私人 memory 隔离；同时行动使用相同截止点。
3. **记忆协议**：每轮追加一条、旧文保持原样、三种 view 正确、压缩输入来自全部原始 bullets。
4. **恢复与采样**：单边响应后中断再恢复，复用已有调用并结算一次；新轮次的相同 prompt 触发新采样。
5. **预算与计费**：seller/压缩/重试均被记录，在途调用预留有效，恢复后累计费用连续。
6. **分析与分叉**：人工构造小数据验证 CI、成功标准、parent 血缘与按 run/parent 分组统计。

Mock 流程覆盖运行、导出、作图、快照和恢复。一次很小的真实 smoke 验证认证与格式，完整 pilot 验证行为和成本。后续按实际变更运行相关测试，在阶段提交前运行现有完整测试集。测试通过后推进实验。
