The current client does not expose a cloud Desktop tab. Opening an ordinary in-app browser at `127.0.0.1` does not establish access to the VM's listener. The unusable VM login attempt was stopped; no credentials or experimental responses were generated by it.

The supported alternative is local OAuth with the same application, followed by protected credential transfer as described in the official VM guide above. An authenticated Remote Desktop Commander connection can run the local helper and carry an encrypted transfer envelope. The user's registered device currently reports offline; it must be brought online before this path can execute.

Follow [Desktop Commander's official Mac connection instructions](https://desktopcommander.app/help/devices/connect-computer). Its launcher opens device verification in the browser; compare the displayed code, select **Verify device**, and keep the terminal open until the handoff is complete. This enables the connected assistant to run commands on that computer. It is separate from the subsequent **Continue with ChatGPT** consent for **IE498 Memory Pricing**.

The application handoff uses a one-use VM public key: the laptop encrypts only this application's freshly authorized credential record, and only the VM can decrypt it. Tokens are never placed in a chat message or printed in process output. The VM verifies the imported identity and retains its original `ext_agent_host_id`. After the authenticated import receipt is verified on the laptop, the local credential copy is retired so the VM owns subsequent rotating-token refreshes. This encryption layer is application code; it does not replace or modify OpenAI's OAuth protocol.

Operator sequence after the device is connected (the same application helpers must be present on each host):

```bash
# VM: produce public metadata; the private recipient key stays on this VM.
python scripts/subscription_handoff.py prepare --output data/auth/handoff-request.json

# Laptop: after receiving only the public request through the authenticated device connection.
python scripts/subscription_login.py --begin --open-browser
python scripts/subscription_handoff.py seal \
  --input data/auth/handoff-request.json --output data/auth/handoff-ciphertext.json

# VM: after receiving only the encrypted envelope from the laptop.
python scripts/subscription_handoff.py import \
  --input data/auth/handoff-ciphertext.json --output data/auth/handoff-receipt.json

# Laptop: after returning the authenticated receipt to the laptop.
python scripts/subscription_handoff.py retire-local --input data/auth/handoff-receipt.json
```

Use `--auth-file` if the helper is deployed outside this repository layout. Transfer requests expire after 30 minutes by default. Generate the recipient request only after the device connection is ready. Do not refresh the laptop session after sealing it. A failed import leaves the laptop's source credentials intact; a tampered or mismatched receipt cannot retire them. After successful import and retirement, resume on the VM with the command below.
